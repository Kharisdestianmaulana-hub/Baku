# 2026-10-09

## Analisis menyeluruh folder proyek Baku (read-only)

Dilakukan audit struktur + kode tanpa mengubah file apa pun.

Temuan utama:
- Stack aktual = Tauri v1.5 (Rust shell) + WebView HTML/JS (Quill 2.0.2 + html2pdf 0.10.1 dari CDN), BUKAN Rust + Slint seperti tertulis di PRD.md → PRD sudah usang/divergen.
- Logika inti ada di `src/main.js` (2711 baris, satu file monolitik) + `src/index.html` (939 baris) + `styles.css` (486) + `i18n.js` (369) + `tooltip.js` (208) + `workspace.js` (70).
- Ekspor PDF memakai `html2pdf.js` (raster/jpeg) di sisi JS, bukan `printpdf`/`lopdf`. Command Rust `export_pdf()` di `src-tauri/src/main.rs` tidak pernah dipanggil dari UI → dead code + dependency bloat.
- CSP di `tauri.conf.json` hanya mengizinkan `script-src 'self' 'unsafe-inline'`, padahal index.html memuat Quill & html2pdf dari jsdelivr/cdnjs → berpotensi diblokir di build Tauri.
- `error_log.txt` menunjuk URL `http://127.0.0.1:1430` → pengembangan tampaknya diuji di browser biasa, bukan di window Tauri, sehingga semua API `window.__TAURI__` tidak aktif.
- Sisa skrip debugging yang melanggar PERATUAN.md (larangan edit via terminal): `src/fix.js`, `fix2.js`, `fix3.js`, `fix4.js`, `replace.js`. Akibatnya ada perilaku rusak: `btn-unsaved-discard` hanya `console.log` (jendela tidak benar-benar ditutup), setTitle dihapus, `text-change` handler di-`return` lebih awal.
- File mati/tidak terpakai: `src/quill2.js` (209KB, tidak direferensikan), `src/test.html`, `src/test-quill.js`, `scratch.html`, `Hasil_Ekspor_Baku.pdf`.
- Git repo belum punya commit sama sekali (`master`, no commits) padahal `.git` sudah ada.
- i18n: dictionary `i18n.js` sudah punya entri (Umum, Editor & Teks, Ekspor & Simpan, Lanjutan), tapi elemen tab Settings di index.html belum diberi `data-i18n` → tidak ikut diterjemahkan.
- Duplikasi blok komentar di main.js baris 1937 & 1967 ("LOGIKA MELAYANG BEBAS & DRAG GAMBAR").

Aturan proyek yang wajib dipatuhi: `PERATUAN.md` (no terminal-based editing, wajib i18n ID+EN via `window.t()`/`data-i18n`, satu fungsi satu tugas, wajib tombol di Ribbon untuk fitur baru, `node --check` setelah perubahan besar).

## Investigasi BUG KRITIS: app "ketutup sendiri" saat New Document / Open .baku

**Kesimpulan: BUKAN bug JS.** Proses native Baku.exe CRASH (bukan window ditutup kode).

Bukti:
- Windows Event Log: 4× crash `Baku.exe` — `Exception code 0xc0000005` (ACCESS_VIOLATION), `Event Name: BEX64`, `P9=0x8` (eksekusi memori non-executable), faulting module **unknown**, fault offset **0x1e31110** (identik di 12:41:56, 12:43:32, 12:54:07, 12:57:28).
- Direproduksi (tanpa mengubah file user): server statis di 127.0.0.1:1430 + Baku.exe (dev build, URL `127.0.0.1:1430` ter-embed).
  - KONTROL tanpa interaksi → app hidup >30 detik.
  - Auto-klik "Buat Dokumen" → `Segmentation fault`.
  - Halaman minimal + SATU `fs.writeTextFile()` → file dibuat **0 bytes** + proses mati.
  - Halaman minimal + SATU `invoke('export_pdf')` (perintah Rust kustom) → proses mati juga.
  - ⇒ **SETIAP panggilan JS→Rust (IPC/invoke) mematikan proses**, bukan hanya fs.
- Bukti fisik: `~/Baku PDF Workspace/Dokumen_Baru.baku` = **0 bytes** (file dibuka/truncate lalu proses mati sebelum isi tertulis).

Mengapa hanya New/Open: `main.js:359` `fs.writeTextFile` (New) & `main.js:1532` `fs.readTextFile` (Open) → crash. Save TIDAK crash karena `writeTextFile` di `main.js:1340` **di-comment** ⇒ konsekuensinya Save tidak pernah menulis ke disk (bug terpisah, data hilang).

Dugaan akar masalah: version skew ekstrem SDK WebView2 kuno vs Runtime baru.
- `tauri 1.8.3`, `wry 0.24.12`, `tao 0.16.11`, `webview2-com 0.19.1`, `rfd 0.10.0` (2023–2024) vs WebView2 Runtime **154.0.4258.62** (terpasang 2026-10-06, 3 hari sebelum crash).
- Diperparah: `src-tauri/build.rs` memakai `tauri_build::try_build` + error diabaikan → manifest Windows tidak ter-embed (resource.rc hanya VERSIONINFO, tanpa `dpiAware`/`PerMonitorV2`).
- Skew lain: `@tauri-apps/cli 1.6.3` vs crate `tauri 1.8.3`.

Catatan lingkungan penting:
- WebView2 user data app ada di `%LOCALAPPDATA%\com.baku.dev\EBWebView` dan **cache disk-nya bisa menyajikan index.html/main.js basi** (ini sempat membuat eksperimen saya menyesatkan). Backup cache lama saya pindahkan ke `%LOCALAPPDATA%\com.baku.dev.cache_dari_tes`, folder asli sudah dikembalikan.
- Python server probe & skrip tracer ada di `%TEMP%\baku_*.py|js|html` (boleh dihapus).
- Tidak ada `.dmp` di Crashpad (crash di host process, bukan renderer).

Rencana perbaikan yang disarankan: (1) uji dengan WebView2 Fixed Version lama via env `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER`; (2) migrasi ke Tauri v2; (3) perbaiki build.rs + allowlist `window`; (4) hidupkan kembali writeTextFile di actionSave, kembalikan handler `text-change` (di-`return` oleh fix4.js), hapus skrip debug fix*.js/replace.js.
